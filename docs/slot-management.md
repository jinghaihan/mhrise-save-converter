# Character-slot safety and verification

For GUI instructions, see [Character-slot management](../README.md#character-slot-management).

The operation coordinates system summaries, character filenames and internal slot metadata, and album prefixes. It keeps the same account and platform, copies unrelated regular files unchanged, and does not edit the original save. Deletion restores a complete empty hunter summary, reusing a source empty slot when available. When all three slots are occupied, it uses an owner-free 16.0.2.0 empty summary adapted to the platform only for matching, recognized schemas; unsupported layouts are rejected before writing. System alignment padding may be regenerated when a shorter empty summary shifts later fields; every unrelated parsed field is verified unchanged. Existing output directories, incomplete or inconsistent bundles, and subdirectories/symlinks are rejected. Clicking the output Browse button selects a parent directory and proposes a new `swapped-save` subfolder.

Steam summaries include a character-consistency ID that must match the character file. Switch summaries do not contain that Steam-only field; occupied and empty slots are identified by their HR/MR markers, then checked against character-file presence, the hunter ID, and internal slot metadata. Switch slot management does not require a SteamID64 or Curve Index.

Portable `.hunter` packages contain one decrypted role, its selection summary, account-independent album files, and a versioned manifest. Import supports the same platform, rebinds initialized Steam owner identities and album wrappers to the destination account, and updates only the selected destination slot. Occupied slots require explicit confirmation. A hunter already present in another slot is rejected. Unknown ZIP entries, duplicate paths, unsafe names, oversized archives, and inconsistent payloads are rejected without publishing output. Packages are not encrypted and should be shared with the same care as saves.

Renaming changes only `LoadInfoSingleData._HunterName` and `GuildCardSaveData.MyData.HunterName`. Historical arena entries and other guild cards retain their original names, even when their text matches the old hunter name. The owner name must match the source summary before editing. Names are limited to 12 UTF-16 code units with no blank-only values or control characters. Rename, movement, and deletion can be saved together; edits follow original hunter identities through moves.

Steam and Switch container tests cover exchanges, empty destinations, round trips, deletion from full bundles, deletion of every character, combined moves/deletions, and integrity checks. Real Steam deletion checks verify surviving character/album bytes and every unrelated system field. A real Switch 10.0.3 JKSV export was checked for inspection, moves into an empty slot, round-trip preservation of every parsed field, and deletion before and after moving the character. Its empty summary also matches the platform-adapted fallback. Slot deletion has not been tested in-game. This is not a guarantee that slot edits fix every loading error; new outputs still need an in-game test.
